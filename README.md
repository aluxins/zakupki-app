# zakupki-app

Основное приложение информационной системы для работы с государственными закупками по **44-ФЗ и 223-ФЗ**.

Приложение предназначено для сбора, обработки, анализа и поиска информации о закупках, а также для организации работы пользователей с полученными данными и документацией закупок.

## Архитектура системы

Проект состоит из двух взаимосвязанных сервисов:

1. **zakupki-app** — основное пользовательское приложение. Отвечает за получение информации о закупках, хранение данных, управление задачами и предоставление инструментов для работы пользователей.
2. **zakupki-file-idx** — поисковая машина. Отвечает за загрузку, извлечение текста, индексацию и полнотекстовый поиск по документам закупок.

Исходный код поискового сервиса находится в отдельном репозитории:

[zakupki-file-idx](https://github.com/aluxins/zakupki-file-idx)

## Основные возможности

### Получение информации о закупках

Приложение использует два независимых источника получения информации:

- **REST API gosplan.info** — получение информации о закупках через внешний API.
- **zakupki.gov.ru** — получение информации посредством парсинга официального сайта государственных закупок.

Для организации процессов сбора информации используются механизмы Laravel Schedules и очереди заданий ShouldQueue.

Полученные сведения о закупках сохраняются в базе данных MySQL.

### Работа с закупками

Пользовательский интерфейс построен на базе административной панели [MoonShine](https://getmoonshine.app/).

Пользователям доступны инструменты отбора и обработки закупок по различным параметрам:

- Дата публикации и другие временные параметры.
- Начальная (максимальная) цена контракта.
- Регион размещения закупки.
- Ключевые слова и поисковые фразы, встречающиеся в документах закупки.
- Срок поставки товаров или оказания услуг.

Полученные закупки могут использоваться для дальнейшего анализа и поиска необходимой информации в документации.

### Индексация документов закупок

После получения информации о закупке приложение формирует список интернет-адресов связанных с ней документов и передает его поисковому сервису **zakupki-file-idx**.

Передаваемые сведения включают:

- Идентификатор документа.
- URL для скачивания документа.
- Регистрационный номер закупки (`reg_number`).

Индексация выполняется асинхронно посредством задания:

`app/Jobs/FilesIndexing.php`

Поисковый сервис самостоятельно загружает документы, извлекает текст и сохраняет его в поисковом индексе Manticore Search.

Таким образом, содержимое документов связывается с регистрационным номером соответствующей закупки.

### Полнотекстовый поиск

Для интеграции с поисковой машиной используется Laravel Scout.

Это позволяет работать с поисковым сервисом Manticore Search через привычную для Laravel модельную архитектуру, аналогично работе с Eloquent.

Пользователь получает возможность искать информацию непосредственно в содержимом документов закупок, а не только в структурированных полях базы данных основного приложения.

Реализация поисковой машины находится в отдельном репозитории:

[zakupki-file-idx — полнотекстовая индексация и поиск документов](https://github.com/aluxins/zakupki-file-idx)

### Определение срока поставки с использованием искусственного интеллекта

В приложении реализована интеграция с [OpenRouter](https://openrouter.ai/) для определения крайнего срока поставки товаров или оказания услуг по закупке.

Проблема заключается в том, что в документации закупок дата исполнения обязательств часто указывается не в виде конкретной календарной даты, а в виде относительного срока:

- В течение определенного количества календарных дней.
- В течение определенного количества рабочих дней.
- В течение срока, определяемого условиями договора.

Кроме того, конкретные даты могут указываться в документах в произвольных форматах.

Для решения этой задачи используется языковая модель искусственного интеллекта.

Общий алгоритм работы:

1. Определяется предполагаемая дата заключения контракта. Для этого используется дата окончания подачи заявок с учетом дополнительного времени, необходимого для проведения процедуры и оформления документов.
2. Текст договора передается через OpenRouter выбранной модели искусственного интеллекта.
3. Модель анализирует условия договора, определяет срок исполнения обязательств и рассчитывает крайнюю дату поставки относительно предполагаемой даты заключения контракта.
4. Полученный результат используется приложением при работе с закупками.

Таким образом, система позволяет автоматически извлекать сроки поставки даже в тех случаях, когда в документации отсутствует явно указанная календарная дата.

## Технологический стек

| Компонент | Назначение |
|---|---|
| Laravel | Основной PHP-фреймворк |
| MoonShine | Административная панель и пользовательский интерфейс |
| MySQL | Хранение информации о закупках |
| Laravel Schedules | Планирование задач сбора информации |
| Laravel Queues / ShouldQueue | Асинхронная обработка задач |
| Laravel Scout | Интеграция с полнотекстовым поиском |
| Manticore Search | Поиск по содержимому документов |
| OpenRouter | Интеграция с языковыми моделями ИИ |

## Взаимодействие с zakupki-file-idx

Основное приложение и поисковая машина являются самостоятельными сервисами, взаимодействующими через REST API.

Основной сценарий взаимодействия:

1. zakupki-app получает информацию о закупке.
2. Сохраняет сведения о закупке в MySQL.
3. Передает список документов в zakupki-file-idx.
4. zakupki-file-idx загружает документы и выполняет индексацию.
5. zakupki-app использует Laravel Scout для поиска по проиндексированным документам.
6. Пользователь получает результаты поиска в контексте соответствующей закупки.

Подробное описание API и механизмов индексации приведено в документации поискового сервиса:

[README.md — zakupki-file-idx](https://github.com/aluxins/zakupki-file-idx#readme)
